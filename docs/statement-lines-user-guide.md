# คู่มือ Statement Lines (`/bank-statement-sync`)

สำหรับผู้ปฏิบัติงาน — หน้าจออยู่ใน **kcw-v2** ที่ `/bank-statement-sync`

FAQ ชุดนี้ถูก seed ลง `kb.kb_parts` (id 136–147) เพื่อถามผ่าน LINE chatbot  
รายการหัวข้อและการตรวจ embedding อยู่ที่ [statement-lines-operator-faq.md](./statement-lines-operator-faq.md)

## หลักการสำคัญ

1. **รายงาน Cashflow BI อ่านจาก `ประเภทการจับคู่` (matched_ref_type)**  
   ถ้าไม่ใส่ ประเภท → ยอดจะไปกอง **“ยังไม่จัดประเภท / อื่นๆ”** แม้จะเขียนเหตุผลไทยแล้วก็ตาม
2. **บันทึกเป็น “จับคู่ด้วยมือ” หรือ “ตรวจแล้ว” ต้องมีทั้ง**
   - เหตุผล (สั้นๆ เป็นไทย)
   - **ประเภทการจับคู่** (บังคับ)
   - เลขอ้างอิง (ถ้ามี เช่น เลขใบสำคัญ / เลขบัญชีคู่)
3. **สถานะ “ไม่ใช้”** = ไม่เอาแถวนี้เข้า Excel รายงาน และไม่นับใน Cashflow (เช่น แถวซ้ำจากไฟล์ statement คนละฟอร์แมต)

## ปุ่มสถานะ — ใช้อะไรเมื่อไหร่

| สถานะบนจอ | ใช้เมื่อ |
|---|---|
| **ต้องตรวจ** | เอเจนต์ส่งมาให้คนดู (วันที่ไม่ตรง / กำกวม / อาจซ้ำ) |
| **ตรวจแล้ว** | ตรวจคิว “ต้องตรวจ” แล้ว ยอมรับการจับคู่ (หรือแก้เหตุผล/ประเภทแล้วโอเค) |
| **จับคู่ด้วยมือ** | คนจับคู่เองเมื่อเอเจนต์จับไม่ได้ หรือเหตุผลเดิมไม่ครบ |
| **ไม่ใช้** | ยืนยันว่าเป็น **แถวซ้ำ / ไม่ต้องรายงาน** (โดยเฉพาะข้อความประมาณ “อาจเป็นแถวซ้ำ”) |
| **ส่งกลับรอจับคู่** | ให้เอเจนต์รันใหม่ (ล้างผลจับคู่เดิม) |
| **จับคู่แล้ว / ยังไม่ประมวลผล / จับคู่ไม่ได้** | ส่วนใหญ่เป็นงานเอเจนต์ — คนไม่ต้องตั้งเอง ยกเว้นส่งกลับคิว |

**อย่าใช้ “ไม่ใช้”** กับดอกเบี้ย / ภาษีหัก ณ ที่จ่าย / โอนภายใน — พวกนี้ต้อง **จับคู่** ด้วยประเภทด้านล่าง

## ประเภทการจับคู่ที่ควรใส่ (ภาษาอังกฤษตามระบบ)

พิมพ์ในช่องประเภทให้ตรงตัวอักษรนี้ (ตัวเล็กตามนี้)

### เงินเข้า

| สถานการณ์ | ใส่ประเภท | เลขอ้างอิงแนะนำ |
|---|---|---|
| Shopee / Lazada / TikTok | `rvi` | เลข RVI ถ้ามี |
| บิลโอน 1 ใบ | `tr_bill` | เลข TR… |
| บิลโอนหลายใบรวมยอด | `tr_bundle` | TR…,TR… |
| ส่วนต่าง / เหลือจากบิลโอน | `tr_remainder` | เลขที่เกี่ยวข้อง |
| ยอดขายสุทธิ TAR−CNTAR | `tar_cntar_net` | วันที่/รหัสที่เกี่ยวข้อง |
| ใบสำคัญรับเงิน (RC…) | `rvmas` | เลข RC… |
| ดอกเบี้ยเงินฝาก | `interest_income` | รหัสอ้างอิงธนาคาร |
| โอนจากบัญชีบริษัทอื่นในกลุ่ม | `internal_transfer` | เลขบัญชีเต็ม เช่น `248-0-42113-9` |
| เงินคืนจากผู้ขาย | `vendor_rebate` | — |
| ปรับปรุงยอดขาย / โอนคืน 3CTAR | `sales_adjustment` | — |

### เงินออก

| สถานการณ์ | ใส่ประเภท | เลขอ้างอิงแนะนำ |
|---|---|---|
| ใบสำคัญจ่าย PARTS9 (PVMAS) | `pvmas` | เลขใบสำคัญ |
| บิลซื้อ PIMAS / ถึงเบิกเลย | `pimas` | เลขบิล |
| เช็คเคลียร์ที่ยังไม่ชัด | `bank_cheque` | เลขเช็ค |
| ค่าใช้จ่ายแอป (PV / 3PV) | `expense_pv` | เลข PV… |
| เงินเดือน | `expense_payroll` | รอบเงินเดือน |
| พนักงานเบิกล่วงหน้า | `employee_advance` | ชื่อ/บัญชีพนักงาน |
| ภาษีหัก ณ ที่จ่าย (ดอกเบี้ย) | `withholding_tax` | รหัสเดียวกับแถวดอกเบี้ย |
| โอนไปบัญชีบริษัทในกลุ่ม | `internal_transfer` | เลขบัญชีคู่ |

**อย่าพิมพ์** `PIMAS` ตัวใหญ่ / ช่องว่าง / ชื่อไทยในช่องประเภท — ระบบจะไม่จัดกลุ่ม BI ถูก

## คิวที่ควรไล่ทุกวัน / ทุกสัปดาห์

1. กรอง **ต้องตรวจ**
   - ถ้าเหตุผลมีคำว่า **อาจเป็นแถวซ้ำ** → เทียบแถวคู่ แล้วกด **ไม่ใช้** ที่แถวที่รายละเอียดสั้น/ซ้ำกว่า
   - ถ้าจับคู่ถูกแต่คนยืนยัน → ใส่ประเภทให้ครบ แล้ว **ตรวจแล้ว**
2. กรอง **จับคู่ไม่ได้** ที่ยังค้างนาน → จับด้วยมือ + ประเภท หรือรอเอกสารแล้วส่งกลับคิว
3. อย่าปล่อยแถว **จับคู่ด้วยมือ** โดยไม่มีประเภท
